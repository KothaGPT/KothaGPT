# Evaluation

Benchmark suites:
- Bengali language quality
- English quality
- instruction following
- coding
- reasoning
- mathematics
- hallucination
- safety
- RAG
- agent/tool use
- latency and throughput

Every model release should have a reproducible evaluation report.

Per-family SFT suites live in `evals/suites/sft-*.yaml` and select matching
files from `data/benchmarks/sft/v1/`. For example:

```bash
python -m evals.run --suite evals/suites/sft-bn.yaml --split dev
```

Text suites report exact and normalized completion matches; function-call and
tool-use suites also compare parsed JSON structures. `mock` returns the gold
output for harness checks. Use `--target predictions --predictions FILE` to
score externally generated outputs by `record_id`.

Benchmark JSONL records may include a `family` field; the runner then emits
family-level metric summaries separately from the overall task aggregates.

Run the context-grounded QA baseline with `make eval-hallucination`. Its
`context_token_coverage` and `lexical_unsupported_token_rate` measure lexical
overlap between answer tokens and the supplied context. They are diagnostic
baselines, not semantic hallucination detectors; an empty answer reports zero
for both metrics and should be tracked separately as a response-quality issue.

To score outputs generated by a model or external pipeline, provide a JSONL
file with one `record_id` and `prediction` per row:

```bash
python -m evals.run \
	--suite evals/suites/hallucination.yaml \
	--data-dir data/benchmarks/hallucination/v1 \
	--target predictions \
	--predictions predictions.jsonl \
	--compare-predictions sft-predictions.jsonl \
	--name hallucination
```

`--compare-predictions` adds candidate-minus-baseline metric deltas overall and
by task family. For the unsupported-token rate, a negative delta means fewer
answer tokens are absent from context. This is a descriptive comparison, not a
significance test.
